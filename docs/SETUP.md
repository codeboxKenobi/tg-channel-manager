## 1. Что нужно для работы

| Компонент | Требование | Зачем |
|---|---|---|
| Node.js | **20.6 или новее** (рекомендуется 22 LTS) | флаг `--env-file`, `fetch`, `AbortSignal.timeout` |
| PostgreSQL | 14+ (в `docker-compose.yml` — 16) | хранение всех данных |
| Исходящий доступ в интернет | `api.telegram.org` и `t.me` по HTTPS | публикация постов, подключение каналов (Bot API); парсер читает веб-версию `t.me/s/…` |
| Входящий доступ для Telegram | публичный HTTPS-адрес с валидным сертификатом (`PUBLIC_URL`), порт 443/80/88/8443 | боты получают события (лайки) через webhook; для разработки на localhost не нужен (polling) |
| Диск | папка для загрузок (по умолчанию `./data/uploads`) | картинки и видео постов |
| Для продакшена | домен и HTTPS (nginx/Caddy) | шифрование трафика, Secure-cookie |

Приложение — **один процесс**: интерфейс (Nuxt), API (Express на `/api/*`), боты и планировщик публикаций работают вместе. Отдельного бэкенда нет.

> **Один экземпляр.** Не запускайте приложение дважды (PM2 cluster, две копии контейнера): планировщик публикаций задвоится и посты уйдут дважды. В режиме polling два процесса с одним токеном ещё и конфликтуют (ошибка 409 от Telegram).

**Как боты получают события.** Единственное, что приходит от Telegram, это нажатия кнопки «👍». На сервере (`PUBLIC_URL` с `https://`) каждый бот работает через **webhook**: Telegram сам присылает события на `PUBLIC_URL/api/telegram/<id администратора>`, постоянных соединений и опроса нет, поэтому нагрузка не растёт с числом администраторов. Без `PUBLIC_URL` (локальная разработка) бот работает через **long polling**: приложение само опрашивает Telegram. Режим выбирается автоматически, его можно зафиксировать через `BOT_MODE=polling`.

## 2. Быстрый старт для разработки

```bash
git clone <репозиторий> tg-channel-manager && cd tg-channel-manager

docker compose up -d            # PostgreSQL 16 на localhost:5433 (база tgm)
cp .env.example .env            # затем заполните SECRETS_KEY (раздел 3.2)
npm install

npm run doctor                  # проверка окружения
npm run dev                     # http://localhost:3000
```

Таблицы создаются сами при старте (раздел 4). При первом входе откроется форма создания главного администратора.

Демо-данные (по желанию): `npm run seed` создаёт администратора `admin@example.com`, редактора `editor@example.com`, тестовые каналы и посты. Пароли печатаются в консоль (пароль админа можно задать в `ADMIN_PASSWORD`).
**`seed` очищает все таблицы. Не запускайте его на рабочей базе.**

## 3. Заполнение .env

```bash
cp .env.example .env
chmod 600 .env                  # файл содержит секреты: только владельцу
```

`.env` читают `npm run dev`, `npm start`, `npm run migrate`, `npm run seed`, `npm run doctor` и PM2-конфиг `ecosystem.config.cjs`. Для Docker значения берутся из `.env` рядом с `docker-compose.prod.yml`. Файл `.env` добавлен в `.gitignore`, не коммитьте его.

### 3.1. Справочник переменных

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `DATABASE_URL` | **да** | — | подключение к PostgreSQL |
| `SECRETS_KEY` | **да** (для подключения ботов) | — | ключ шифрования токенов ботов в БД, 32 байта |
| `BOT_TOKEN` | нет | — | бот по умолчанию **только для главного администратора** |
| `ALLOW_REGISTRATION` | нет | `true` | `false` отключает самостоятельную регистрацию |
| `REGISTRATION_CODE` | нет | пусто | код-приглашение: если задан, без него не зарегистрироваться |
| `PUBLIC_URL` | **да для продакшена** | — | публичный HTTPS-адрес приложения без `/` в конце (`https://tgm.example.com`). Если задан, боты работают через webhook |
| `BOT_MODE` | нет | `auto` | `polling` принудительно включает polling даже при заданном `PUBLIC_URL`; `auto`/`webhook` — webhook, если есть `PUBLIC_URL` |
| `TRUST_PROXY` | нет | `false` | `true`, если приложение за reverse proxy с HTTPS |
| `PORT` | нет | `3000` (PM2-конфиг: `8080`) | порт приложения |
| `UPLOAD_DIR` | нет | `./data/uploads` | папка загруженных картинок и видео |
| `DB_PASSWORD` | только для `docker-compose.prod.yml` | — | пароль PostgreSQL в продакшн-compose |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | только для `npm run seed` | `admin@example.com`, случайный | логин и пароль демо-администратора |
| `ALLOW_PLAINTEXT_PASSWORD` | нет | выключено | `true` разрешает отправлять пароли в открытом виде (для `curl` и скриптов). В обычной работе не включайте |

### 3.2. Как заполнить, шаг за шагом

**1. `DATABASE_URL`** — адрес базы в формате `postgres://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@ХОСТ:ПОРТ/ИМЯ_БАЗЫ`.

| Ситуация | Значение |
|---|---|
| База из `docker-compose.yml` (разработка) | `postgres://tgm:samaellilith@localhost:5433/tgm` (уже стоит в `.env.example`) |
| Своя БД на этом же сервере | `postgres://tgm:ВАШ_ПАРОЛЬ@localhost:5432/tgm` |
| Внешний сервер или облачная БД | `postgres://user:pass@db.example.com:5432/tgm` (если провайдер требует SSL, добавьте `?sslmode=require`) |
| Docker-продакшн (`docker-compose.prod.yml`) | задавать **не нужно**: compose собирает адрес сам из `DB_PASSWORD` |

Спецсимволы в пароле кодируйте: `@` → `%40`, `#` → `%23`, `/` → `%2F`, `:` → `%3A`, `%` → `%25`. Пароль из букв и цифр проще.

**2. `SECRETS_KEY`** — случайные 32 байта. Сгенерируйте и вставьте результат:

```bash
openssl rand -base64 32
# без openssl:
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

- Подходит base64 (44 символа, оканчивается на `=`) или 64 hex-символа.
- Ключ шифрует токены ботов в БД (AES-256-GCM). **Сохраните копию отдельно от БД** (менеджер паролей). Если ключ потерян или изменён, токены станут нечитаемыми, и администраторам придётся ввести их заново на странице «Бот». Остальные данные не пострадают.
- Не меняйте ключ без необходимости: для нового сервера с чистой БД можно сгенерировать новый, а при переносе существующей БД ключ должен остаться прежним.

**3. `BOT_TOKEN`** — необязателен. Нужен, только если вы хотите, чтобы главный администратор сразу работал с уже существующим ботом (например, после обновления со старой версии, где бот был один на всех). Токен выдаёт @BotFather. Остальные администраторы подключают **своих** ботов на странице «Бот»; чужой бот и бот из `BOT_TOKEN` им подключить нельзя.

**4. Регистрация.** По умолчанию любой может зарегистрироваться администратором со своим пустым пространством. Для публичного сервера выберите:

- закрыть: `ALLOW_REGISTRATION=false` (администраторов создаёт главный администратор на странице «Пользователи»);
- или оставить открытой по коду: `REGISTRATION_CODE=длинная-случайная-фраза` (код вводится на странице регистрации).

Ограничения: не больше 10 попыток регистрации в час с одного IP; не больше 50 источников парсера на пространство. Подтверждения email нет (в проекте нет почты).

**5. `PUBLIC_URL`** — адрес, по которому Telegram достучится до вашего сервера: `https://tgm.example.com` (домен из nginx, без `/` в конце, без `/api`). Требования Telegram: HTTPS с **валидным** сертификатом (самоподписанный не подойдёт), порт 443, 80, 88 или 8443. На локальной машине оставьте переменную пустой: боты будут работать через polling. Приложение само регистрирует webhook у Telegram при подключении бота и при каждом старте.

**6. `TRUST_PROXY`** — поставьте `true`, если перед приложением стоит nginx/Caddy с HTTPS: тогда cookie сессии получает флаг `Secure`, а IP клиентов берутся из `X-Forwarded-For`. Если приложение открыто напрямую по `http://`, оставьте `false`. Поставите `true` без прокси, и клиент сможет подделывать свой IP.

**7. `PORT`, `UPLOAD_DIR`** — по необходимости. Папка `UPLOAD_DIR` должна существовать или создаваться (приложение создаёт её само) и быть доступной на запись пользователю, под которым запущен процесс. Относительные пути считаются от папки запуска, для продакшена удобнее абсолютный: `UPLOAD_DIR=/var/lib/tgm/uploads`.

### 3.3. Готовые примеры

**Разработка** (`.env`):

```ini
DATABASE_URL=postgres://tgm:samaellilith@localhost:5433/tgm
SECRETS_KEY=сюда_результат_openssl_rand_-base64_32
BOT_TOKEN=
ALLOW_REGISTRATION=true
REGISTRATION_CODE=
TRUST_PROXY=false
```

**Продакшн на своём сервере** (PM2 или systemd, nginx с HTTPS):

```ini
DATABASE_URL=postgres://tgm:НАДЁЖНЫЙ_ПАРОЛЬ@localhost:5432/tgm
SECRETS_KEY=сюда_результат_openssl_rand_-base64_32
BOT_TOKEN=
ALLOW_REGISTRATION=true
REGISTRATION_CODE=длинная-случайная-фраза
PUBLIC_URL=https://tgm.example.com
TRUST_PROXY=true
PORT=3000
UPLOAD_DIR=/var/lib/tgm/uploads
```

**Docker-продакшн** (`docker-compose.prod.yml`, `.env` рядом с ним):

```ini
DB_PASSWORD=НАДЁЖНЫЙ_ПАРОЛЬ
SECRETS_KEY=сюда_результат_openssl_rand_-base64_32
BOT_TOKEN=
ALLOW_REGISTRATION=true
REGISTRATION_CODE=длинная-случайная-фраза
PUBLIC_URL=https://tgm.example.com
```

(`TRUST_PROXY=true` и `DATABASE_URL` compose выставляет сам.)

После заполнения запустите `npm run doctor`: он проверит формат значений, подключение к БД, ключ, папку загрузок и доступ к Telegram.

## 4. База данных

### 4.1. Что создаётся автоматически, а что вручную

| | Кто создаёт |
|---|---|
| Сервер PostgreSQL | **вы** (или `docker compose up -d`) |
| Пользователь и пустая база (`tgm`) | **вы** (или `docker compose`, он создаёт `tgm`/`tgm`) |
| Все таблицы, индексы, колонки, тип `post_status` | **приложение** при старте |
| Перенос старых данных при обновлении (владельцы каналов, главный администратор) | **приложение** при старте |
| Первый администратор | **вы** в браузере (форма при первом входе) |

Схема лежит в `server/express/schema.js` и состоит из команд `create table if not exists` / `add column if not exists`, поэтому она **идемпотентна**: безопасно применяется при каждом запуске, ничего не стирает и не дублирует. Применяется одним запросом, то есть целиком или не применяется вовсе. Расширения PostgreSQL не нужны.

Применить схему вручную, не запуская приложение: `npm run migrate` (печатает «Схема применена»).

### 4.2. Создание базы вручную (если не Docker)

```bash
sudo -u postgres psql
```
```sql
CREATE USER tgm WITH PASSWORD 'НАДЁЖНЫЙ_ПАРОЛЬ';
CREATE DATABASE tgm OWNER tgm;
\q
```

Проверка подключения: `psql "postgres://tgm:НАДЁЖНЫЙ_ПАРОЛЬ@localhost:5432/tgm" -c "select 1"`.
Если PostgreSQL на другом сервере, разрешите подключение в `pg_hba.conf` и `listen_addresses` и откройте порт **только для адреса приложения**.

### 4.3. Таблицы

| Таблица | Содержимое |
|---|---|
| `users` | пользователи: роль (`admin`/`editor`), `owner_id` (у редактора — его администратор), `is_super` (главный администратор), хэш пароля (scrypt) |
| `sessions` | сессии (в БД только sha256 токена), 14 дней; просроченные удаляются ночью |
| `channels` | подключённые Telegram-каналы; `owner_id` — администратор-владелец |
| `channel_users` | закрепление каналов за редакторами |
| `posts` | посты и черновики (статусы `draft`, `scheduled`, `publishing`, `published`, `failed`), медиа, автор |
| `post_likes` | лайки под постами (кнопка 👍) |
| `channel_stats` | почасовые снимки числа подписчиков (метрики) |
| `parser_sources`, `parsed_posts` | каналы-источники парсера и спарсенные посты (со ссылкой на созданный черновик) |
| `workspace_bots` | бот каждого администратора: **зашифрованный** токен, id и @username бота |

Удаление администратора каскадно удаляет его пространство: редакторов, каналы, посты, источники парсера и бота. Файлы из `UPLOAD_DIR` при этом остаются на диске.

### 4.4. Сброс и перенос

- Полностью очистить базу в разработке: `docker compose down -v` (удаляет том с данными), затем `docker compose up -d`.
- Перенос на другой сервер: `pg_dump` на старом, `pg_restore`/`psql` на новом (раздел 8), перенести `UPLOAD_DIR` и **тот же `SECRETS_KEY`**.

### 4.5. Безопасность БД

- `docker-compose.yml` предназначен для **разработки**: он публикует порт `5433` на все интерфейсы и содержит простой пароль. На сервере в интернете его использовать нельзя. Для продакшена берите `docker-compose.prod.yml` (база без внешнего порта, пароль из `DB_PASSWORD`) или свой PostgreSQL с закрытым файрволом портом 5432.
- У пользователя БД должны быть права владельца своей базы (создание таблиц при старте).

## 5. Первый запуск и первичная настройка

1. **Проверьте окружение:** `npm run doctor`. Все ✗ нужно устранить; ⚠ прочитайте.
2. **Запустите** приложение (раздел 2 или 6). В логах должно появиться что-то вроде `Ни у одного администратора не подключён бот…` (на чистой базе это нормально). Если вместо этого есть `Ошибка запуска: …`, смотрите раздел 10: приложение продолжает работать, но API будет отвечать ошибками.
3. **Создайте главного администратора.** Откройте сайт: на пустой базе страница входа предложит создать администратора (email, имя, пароль от 8 символов). Первый пользователь становится **главным администратором**.
4. **Подключите бота.** В Telegram создайте бота у @BotFather, скопируйте токен. В приложении откройте страницу **«Бот»**, вставьте токен, нажмите «Сохранить». Токен проверяется у Telegram, шифруется и сохраняется. Для этого в `.env` должен быть `SECRETS_KEY`. Если задан `PUBLIC_URL`, сразу регистрируется webhook; на той же странице должно появиться «webhook · зарегистрирован» без «последней ошибки доставки».
5. **Добавьте бота администратором канала** (в Telegram: настройки канала → администраторы) с правом публикации сообщений.
6. **Подключите канал:** страница «Каналы» → `@username` или числовой id канала.
7. **Создайте редакторов:** «Пользователи» → «Новый редактор»; закрепите за ними каналы кнопкой «Каналы».
8. **Другие администраторы:** либо они регистрируются сами (ссылка «Зарегистрироваться» на странице входа, если регистрация включена), либо их создаёт главный администратор в разделе «Администраторы». Каждый получает пустое пространство и подключает своего бота.

У каждого администратора свои каналы, редакторы, парсер и бот. Другие администраторы (и главный) их не видят.

## 6. Запуск в продакшене

Во всех вариантах: **один экземпляр**, `.env` заполнен, `npm run doctor` без ✗.

### 6.1. Напрямую (`npm start`)

```bash
npm ci                          # или npm install
npm run build                   # собирает .output/
npm start                       # node --env-file=.env .output/server/index.mjs
```

### 6.2. PM2

```bash
npm ci && npm run build
npm i -g pm2
pm2 start ecosystem.config.cjs
pm2 save && pm2 startup         # автозапуск после перезагрузки сервера (выполните команду, которую выведет pm2)
```

`ecosystem.config.cjs` сам читает `.env` (PM2 запускает приложение напрямую и без этого переменные бы не попали в процесс), запускает **один** экземпляр и по умолчанию слушает порт `8080` (меняется через `PORT` в `.env`).
Окружение PM2 фиксируется при старте. После изменения `.env`:

```bash
pm2 restart ecosystem.config.cjs --update-env
```

Логи: `pm2 logs tg-channel-manager`.

### 6.3. systemd (вместо PM2)

`/etc/systemd/system/tgm.service`:

```ini
[Unit]
Description=tg-channel-manager
After=network-online.target postgresql.service

[Service]
User=tgm
WorkingDirectory=/opt/tg-channel-manager
ExecStart=/usr/bin/node --env-file=.env .output/server/index.mjs
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now tgm
journalctl -u tgm -f            # логи
```

### 6.4. Docker

```bash
# в .env рядом с docker-compose.prod.yml: DB_PASSWORD, SECRETS_KEY, при необходимости REGISTRATION_CODE
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml logs -f app
```

Приложение слушает `127.0.0.1:3000` (наружу его выставляет nginx), база без внешнего порта, загрузки хранятся в томе `uploads` (`/data/uploads`), данные БД в томе `pgdata`. Не удаляйте тома (`down -v`).
Проверка внутри контейнера: `docker compose -f docker-compose.prod.yml exec app node -e "fetch('http://localhost:3000/api/health').then(r=>r.text()).then(console.log)"`.

### 6.5. nginx и HTTPS

Пример для домена `tgm.example.com` (порт `3000`; при PM2-конфиге по умолчанию — `8080`):

```nginx
server {
    listen 80;
    server_name tgm.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name tgm.example.com;
    ssl_certificate     /etc/letsencrypt/live/tgm.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tgm.example.com/privkey.pem;

    client_max_body_size 10m;                 # загрузка картинок в посты (лимит приложения — 10 МБ)

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $http_host;   # именно $http_host: приложение сверяет Origin с Host
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;              # парсинг каналов и скачивание видео бывают долгими
        proxy_send_timeout 300s;
    }
}
```

Сертификат: `sudo certbot --nginx -d tgm.example.com`. В `.env` поставьте `TRUST_PROXY=true` и перезапустите приложение. Если перед nginx есть ещё один прокси (например, Cloudflare), приложение учитывает только один уровень прокси: настройте реальный IP клиента на уровне nginx (`real_ip_header`).

**Webhook Telegram.** Адрес `/api/telegram/…` должен быть доступен Telegram из интернета: не закрывайте его паролем (basic auth), VPN или ограничением по IP, а на файрволе пропускайте входящий 443. Запросы подтверждаются секретом в заголовке `X-Telegram-Bot-Api-Secret-Token`, поэтому пускать только IP Telegram (`149.154.160.0/20`, `91.108.4.0/22`) необязательно, но можно. Cloudflare и подобные прокси работают, если они пропускают POST на этот путь.

**Без HTTPS** (например, `http://IP-адрес`) приложение работает, но пароли, сессии и токены идут по сети открыто. Шифрование паролей и токенов при отправке убирает их из DevTools и логов, но от перехватчика трафика не защищает, который может подменить страницу. Для публичного сервера настройте HTTPS.

### 6.6. Файрвол

Снаружи должны быть открыты только `80` и `443` (и SSH); порт `443` должен быть доступен Telegram (webhook). Порты PostgreSQL (`5432`/`5433`) и приложения (`3000`/`8080`) наружу не открывайте.

## 7. Обновление приложения

1. **Резервная копия** (раздел 8): `pg_dump`, `UPLOAD_DIR`, `.env`.
2. Получите новый код (`git pull`). Если вы ставили возможности через установочные скрипты, они применяются **строго по порядку**:
   `add-parser.mjs` → `add-secure-passwords.mjs` → `add-workspaces.mjs` → `add-isolation.mjs`
   (`node add-….mjs /путь/к/проекту`; каждый безопасен при повторном запуске и ничего не меняет при конфликте).
3. `npm install` (если менялись зависимости) → `npm run build`.
4. Перезапустите приложение (`pm2 restart ecosystem.config.cjs --update-env` / `systemctl restart tgm` / `docker compose … up -d --build`).
   **Схема БД обновится сама при старте.**
5. Если задан `PUBLIC_URL`, боты **сами перейдут с polling на webhook** при первом же старте (вручную ничего делать не нужно). Если нет, они продолжат работать через polling.
6. Обновите страницу в браузере через **Ctrl+F5**, иначе старый JavaScript будет отправлять устаревшие запросы.
7. `npm run doctor` и просмотр логов.

При обновлении со старой версии (один общий бот и общее пространство) при первом старте: администратор с наименьшим `id` становится главным и получает все существующие каналы, редакторов и источники парсера. Остальные администраторы получают пустые пространства. Как передать им каналы, описано в README, раздел «Пароли и роли». Токен из `BOT_TOKEN` продолжит работать для главного администратора, пока он не подключит своего бота.

## 8. Резервные копии

Копировать нужно **три вещи**:

| Что | Как |
|---|---|
| База данных | `pg_dump -Fc "$DATABASE_URL" > tgm-$(date +%F).dump` |
| Загрузки | папка `UPLOAD_DIR` (`tar czf uploads-$(date +%F).tgz /var/lib/tgm/uploads`) или том Docker `uploads` |
| `.env`, в первую очередь `SECRETS_KEY` | в защищённом месте отдельно от БД |

Docker: `docker compose -f docker-compose.prod.yml exec -T db pg_dump -U tgm -Fc tgm > tgm.dump`.

Восстановление в пустую базу: `pg_restore -d "$DATABASE_URL" --no-owner tgm.dump` (для обычного SQL-дампа: `psql "$DATABASE_URL" < tgm.sql`). После восстановления запустите приложение с **тем же `SECRETS_KEY`**: иначе токены ботов не расшифруются, и их придётся ввести заново.

Рекомендуется выполнять копирование по расписанию (cron) и периодически проверять восстановление на тестовой базе.

## 9. Проверка и диагностика

**`npm run doctor`** проверяет и ничего не меняет:

- версию Node.js, наличие `.env` и сборки `.output`;
- корректность `SECRETS_KEY`, `PORT`, настроек регистрации и `TRUST_PROXY`;
- доступность на запись папки загрузок;
- подключение к PostgreSQL, версию, наличие всех таблиц, актуальность схемы, число пользователей/администраторов и подключённых ботов;
- режим ботов (webhook/polling), формат `PUBLIC_URL`, допустимый порт, отвечает ли `PUBLIC_URL/api/health` с самого сервера;
- принимает ли Telegram `BOT_TOKEN` (если задан), доступность `api.telegram.org` и `t.me` с сервера.

Код выхода `1`, если есть критичные проблемы (✗). Флаг `--offline` (`node --env-file=.env scripts/doctor.js --offline`) пропускает сетевые проверки Telegram.

**Проверка работающего приложения:** `curl http://localhost:3000/api/health` → `{"ok":true,"bot":true}`. Поле `bot` показывает, запущен ли хотя бы один бот (до подключения первого оно `false`: это нормально).

**Логи:** `pm2 logs tg-channel-manager` / `journalctl -u tgm -f` / `docker compose … logs -f app`. Токены ботов в логи не попадают.

## 10. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| В логах `Ошибка запуска: …`, страница открывается, но данные не грузятся | миграция не выполнилась (БД недоступна, неверные данные) | `npm run doctor`; исправьте `DATABASE_URL`/доступ, перезапустите |
| `ECONNREFUSED` | PostgreSQL не запущен или неверный хост/порт | запустите БД; для `docker-compose.yml` порт `5433`, не `5432` |
| `password authentication failed` | неверный пароль в `DATABASE_URL` | исправьте; спецсимволы кодируйте (`@` → `%40`) |
| `database "tgm" does not exist` | база не создана | раздел 4.2 |
| `permission denied for schema public` | у пользователя нет прав на базу | `ALTER DATABASE tgm OWNER TO tgm;` |
| Под PM2 `DATABASE_URL` пустой, приложение не подключается к БД | PM2 не читает `.env` | используйте `ecosystem.config.cjs` из репозитория; после правки `.env` — `pm2 restart ecosystem.config.cjs --update-env` |
| Страница «Бот»: «не задан SECRETS_KEY» | переменная не попала в процесс | задайте в `.env`, перезапустите; в Docker проверьте, что она в `.env` рядом с compose |
| «Не удалось расшифровать токен: изменился SECRETS_KEY» | ключ другой, чем при сохранении токена | верните прежний ключ либо введите токен заново на странице «Бот» |
| «Запрос с чужого origin отклонён» (403) при входе или сохранении | прокси подменяет `Host` | в nginx `proxy_set_header Host $http_host;` (не `$host`) |
| Загрузка картинки: `413 Request Entity Too Large` | лимит nginx по умолчанию 1 МБ | `client_max_body_size 10m;` |
| За HTTPS после входа сразу «вылетает» | cookie без `Secure`/неверный IP | `TRUST_PROXY=true` и `X-Forwarded-Proto` в nginx |
| «Ключ шифрования устарел. Повторите попытку» / «Пароль должен передаваться в зашифрованном виде» | в браузере старая версия страницы | Ctrl+F5 |
| В логах Telegram `409: Conflict … getUpdates` | режим polling: тот же токен опрашивает второй процесс | оставьте один экземпляр; задайте `PUBLIC_URL` (webhook) |
| На странице «Бот» «webhook · не зарегистрирован» или «Не удалось зарегистрировать webhook» | `PUBLIC_URL` с неверным портом или не https, Telegram отклонил адрес | исправьте `PUBLIC_URL` (https, порт 443/80/88/8443), перезапустите приложение, `npm run doctor` |
| «Последняя ошибка доставки: … 502 / 404 / SSL error / Connection timed out» | Telegram не достучался до сервера: прокси не пересылает `/api/telegram/`, невалидный сертификат, закрыт порт 443, адрес защищён паролем/IP-фильтром | проверьте `curl -i -X POST https://ваш-домен/api/telegram/1` (ответ 404 означает, что до приложения доходит), сертификат, nginx и файрвол |
| Кнопки «👍» под постами не реагируют | webhook не доходит (см. выше) или бот заменён | статус на странице «Бот»; после смены токена старые кнопки не работают |
| Приложение за прокси, но лайки не приходят после смены домена | `PUBLIC_URL` остался старым | исправьте и перезапустите: webhook перерегистрируется при старте |
| Публикация: «Бот не подключён» | у администратора нет токена на странице «Бот» (или он удалён) | подключите бота |
| «chat not found» / «bot is not a member» при добавлении канала | бот не добавлен в канал или не администратор | добавьте бота администратором с правом публикации |
| Парсер: «Не удалось загрузить t.me», 429 | нет доступа к `t.me` с сервера или Telegram ограничил частоту | `npm run doctor`; повторите позже; уменьшите глубину парсинга |
| Парсер: «Канал не найден или у него отключён публичный просмотр» | канал приватный, нет `@username` или отключён веб-просмотр | подходят только публичные каналы с `t.me/s/…` |
| Не удаётся зарегистрироваться | регистрация отключена, неверный код, превышен лимит попыток | проверьте `ALLOW_REGISTRATION`/`REGISTRATION_CODE`; подождите час |
| Не загружаются картинки/видео | `UPLOAD_DIR` недоступна на запись | права на папку для пользователя процесса; `npm run doctor` |
