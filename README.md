# Менеджер Telegram-каналов — монолит (Nuxt 3 + Express + PostgreSQL)

Одно приложение, один процесс: Nuxt (Vue) отдаёт интерфейс, Express-API смонтирован на `/api/*` внутри сервера Nuxt (Nitro), там же работают бот и планировщик публикаций. Отдельного бэкенда и CORS нет.

## Запуск (Node.js 20.6+)

```bash
docker compose up -d            # PostgreSQL
cp .env.example .env            # впишите BOT_TOKEN
npm install

npm run seed                    # по желанию: демо-данные + пользователи (очищает все таблицы!)
npm run dev                     # http://localhost:3000
```

Таблицы создаются сами при старте приложения (схема идемпотентна; то же делает `npm run migrate`).

**Первый вход.** Если пользователей нет, страница входа предложит создать администратора. Если запускали `npm run seed`, логины и пароли демо-пользователей напечатаны в консоль (пароль админа можно задать в `ADMIN_PASSWORD`).

## Продакшн

```bash
npm run build
npm start                       # node --env-file=.env .output/server/index.mjs (порт — переменная PORT)
```

Запускайте **один** экземпляр: бот работает через long polling, два процесса с одним токеном конфликтуют, а планировщик задвоится.
За reverse proxy с HTTPS (nginx, Caddy) задайте `TRUST_PROXY=true`, иначе cookie сессии не получит флаг `Secure`.

## Авторизация

- Вход по email и паролю. Пароли хранятся как scrypt-хеш с солью.
- Сессия — случайный токен в httpOnly-cookie (`SameSite=Lax`, 14 дней). В БД хранится только его sha256, поэтому сессию можно отозвать: выход, смена пароля и удаление пользователя завершают сессии.
- Защита от подбора: 10 неудачных попыток за 15 минут на пару IP + email, затем ответ 429 (счётчик в памяти процесса).
- CSRF: cookie `SameSite=Lax` плюс проверка заголовка `Origin` у всех запросов, меняющих данные.
- Роли: **администратор** — всё, включая подключение и удаление каналов, управление пользователями; **редактор** — посты и метрики.
- Рабочее пространство общее: все видят все каналы и посты. У постов хранится автор.

## Настройка бота

1. Создайте бота у @BotFather, токен — в `.env` (`BOT_TOKEN`).
2. Добавьте бота администратором канала с правом публикации.
3. Войдите администратором и подключите канал на странице «Каналы» по `@username` или id.

## Загрузка медиа в посты

В форме нового поста можно загрузить картинку (JPEG, PNG, WebP; сжимается в браузере) или **видео MP4** (H.264) до 50 МБ: файл сохраняется как есть, во время загрузки показывается прогресс. Видео QuickTime (.mov) и другие форматы Telegram как видео не принимает: сначала экспортируйте в MP4. Перед nginx нужен `client_max_body_size 50m`. Подробности: [docs/SETUP.md](docs/SETUP.md), раздел 6.7.

## Структура

```
server/middleware/api.ts   монтирует Express на /api/*
server/plugins/bootstrap.ts  миграции → бот → планировщик (один раз на процесс)
server/express/            app, auth, routes, bot, scheduler, db, schema
scripts/                   migrate.js, seed.js
pages/ components/ composables/ middleware/   интерфейс Nuxt
locales/                   тексты интерфейса (ru.ts, en.ts) и перевод сообщений сервера
```

## Язык интерфейса

Интерфейс работает на русском и английском. Язык выбирается на странице «Профиль» (блок «Язык интерфейса») и хранится в аккаунте (`users.lang`), поэтому на другом устройстве интерфейс откроется на том же языке. На страницах входа и регистрации язык переключается кнопками RU / EN; язык, выбранный там, сохраняется в аккаунт. Новый пользователь, которого создаёт администратор, начинает с языком администратора. Язык по умолчанию — русский.

- Тексты лежат в `locales/ru.ts` и `locales/en.ts` (ключи общие, русский — основной), логика — в `composables/useLocale.ts`: `t('ключ', { имя: значение })`, для множественного числа третий параметр — число.
- Сообщения об ошибках сервер по-прежнему пишет по-русски; для других языков клиент переводит их по таблице `locales/server-errors.ts`. Добавили сообщение в `server/express` — добавьте его и в таблицу, иначе оно останется русским.
- Руководство пользователя написано отдельно для каждого языка: `components/GuideRu.vue` и `components/GuideEn.vue`. Правьте оба.
- Чтобы добавить язык: `locales/<код>.ts`, запись в `composables/useLocale.ts`, код в `LANGS` в `server/express/auth.js` и перевод руководства.
- Названия каналов, тексты постов и сообщения, которые бот пишет в Telegram, не переводятся.

## Удаление аккаунтов

- **По желанию пользователя.** На странице «Профиль» блок «Удаление аккаунта»: нужен пароль и подтверждение. Редактор удаляется сам (созданные им посты остаются). Администратор удаляется **вместе со всем своим пространством**: каналами, постами, статистикой, источниками парсера, загруженными файлами, редакторами и ботом (у бота снимается webhook). Главный администратор удалить себя не может.
- **По бездействию.** Раз в сутки (03:30 по времени сервера) удаляются аккаунты, в которые не заходили `INACTIVE_DAYS` дней (по умолчанию **90**; `0` — отключить, значения меньше 7 не принимаются). Редактор удаляется, если не заходил сам; администратор — только если не заходил ни он, ни один из его редакторов. Главный администратор не удаляется никогда. За один запуск удаляется не больше 50 аккаунтов.
- Активность — вход и любые запросы к API под своим аккаунтом (время обновляется не чаще раза в 15 минут, поле `users.last_active_at`). Запланированные публикации активностью не считаются. Предупреждений по почте перед удалением нет.
- Сообщения, уже опубликованные в Telegram-каналах, не удаляются. Восстановить удалённые данные можно только из резервной копии БД.

## Почта

SMTP-почта нужна для двух писем в оформлении приложения: **письмо с логином, паролем и описанием из руководства** новому администратору или редактору и **код восстановления пароля** («Забыли пароль?» на странице входа). Пока `SMTP_HOST` и `MAIL_FROM` не заданы, почта выключена: приложение работает как раньше, а ссылки «Забыли пароль?» нет.

| Переменная | Назначение |
|---|---|
| `SMTP_HOST`, `SMTP_PORT` | сервер и порт (587 — STARTTLS, 465 — TLS сразу) |
| `SMTP_SECURE` | `true` для порта 465 (если пусто, определяется по порту) |
| `SMTP_USER`, `SMTP_PASS` | логин и пароль (у Яндекса, Mail.ru и Gmail — пароль приложения) |
| `MAIL_FROM` | отправитель, например `Менеджер каналов <no-reply@example.com>` (адрес должен принадлежать тому же ящику или домену, что и SMTP-аккаунт) |
| `APP_URL` | адрес приложения для ссылок в письмах; если пусто, берётся `PUBLIC_URL`, затем адрес запроса |

Проверка: `npm run mail:test -- адрес@пример.рф` отправит тестовое письмо и покажет причину, если не вышло.

- **Код восстановления:** 6 цифр, действует 15 минут, 5 попыток ввода; в БД только хеш (таблица `password_resets`). Запросов кода не больше 3 в час на адрес и 10 в час с IP. Ответ не выдаёт, существует ли адрес. После смены пароля все сессии пользователя завершаются.
- **Письмо с доступом:** уходит при создании пользователя на странице «Пользователи». Если отправить не удалось, аккаунт всё равно создаётся, а администратор видит предупреждение. В письме открытый пароль, поэтому пользователю рекомендуется сменить его после первого входа.

## Ограничения

- Bot API не отдаёт просмотры постов канала, поэтому их в метриках нет.
- Опубликованные посты в Telegram не редактируются (только удаляются).
- Seeder использует вымышленные `tg_chat_id`: посты в этих каналах не опубликуются, подключите свой канал.
