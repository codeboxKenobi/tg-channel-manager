# Менеджер Telegram-каналов — монолит (Nuxt 3 + Express + PostgreSQL)

Одно приложение, один процесс: Nuxt (Vue) отдаёт интерфейс, Express-API смонтирован на `/api/*` внутри сервера Nuxt (Nitro), там же работают бот и планировщик публикаций. Отдельного бэкенда и CORS нет.

## Запуск (Node.js 20.6+)

```bash
docker compose up -d            # PostgreSQL
cp .env.example .env            # впишите BOT_TOKEN
npm install

npm run seed                    # по желанию: демо-данные + пользователи (очищает все таблицы!)
npm run dev                     # http://localhost:3000
```

Таблицы создаются сами при старте приложения (схема идемпотентна; то же делает `npm run migrate`).

**Первый вход.** Если пользователей нет, страница входа предложит создать администратора. Если запускали `npm run seed`, логины и пароли демо-пользователей напечатаны в консоль (пароль админа можно задать в `ADMIN_PASSWORD`).

## Продакшн

```bash
npm run build
npm start                       # node --env-file=.env .output/server/index.mjs (порт — переменная PORT)
```

Запускайте **один** экземпляр: бот работает через long polling, два процесса с одним токеном конфликтуют, а планировщик задвоится.
За reverse proxy с HTTPS (nginx, Caddy) задайте `TRUST_PROXY=true`, иначе cookie сессии не получит флаг `Secure`.

## Авторизация

- Вход по email и паролю. Пароли хранятся как scrypt-хеш с солью.
- Сессия — случайный токен в httpOnly-cookie (`SameSite=Lax`, 14 дней). В БД хранится только его sha256, поэтому сессию можно отозвать: выход, смена пароля и удаление пользователя завершают сессии.
- Защита от подбора: 10 неудачных попыток за 15 минут на пару IP + email, затем ответ 429 (счётчик в памяти процесса).
- CSRF: cookie `SameSite=Lax` плюс проверка заголовка `Origin` у всех запросов, меняющих данные.
- Роли: **администратор** — всё, включая подключение и удаление каналов, управление пользователями; **редактор** — посты и метрики.
- Рабочее пространство общее: все видят все каналы и посты. У постов хранится автор.

## Настройка бота

1. Создайте бота у @BotFather, токен — в `.env` (`BOT_TOKEN`).
2. Добавьте бота администратором канала с правом публикации.
3. Войдите администратором и подключите канал на странице «Каналы» по `@username` или id.

## Структура

```
server/middleware/api.ts   монтирует Express на /api/*
server/plugins/bootstrap.ts  миграции → бот → планировщик (один раз на процесс)
server/express/            app, auth, routes, bot, scheduler, db, schema
scripts/                   migrate.js, seed.js
pages/ components/ composables/ middleware/   интерфейс Nuxt
```

## Ограничения

- Bot API не отдаёт просмотры постов канала, поэтому их в метриках нет.
- Опубликованные посты в Telegram не редактируются (только удаляются).
- Seeder использует вымышленные `tg_chat_id`: посты в этих каналах не опубликуются, подключите свой канал.
